Notebook · mid-October to November 2026

From copied model rules to a profile

Agents Collab didn’t start as a product idea. It started as a mess of repeated personal rules across projects, and the slow realisation that they had been put in the wrong place.

  1. 13 Oct 2026

    Per-project model collaboration

    The earlier Model Collaboration skill used per-project setup and local agreements for task choices and review boundaries. A setup check on 13 October confirmed that both the Codex and Claude clients discovered and loaded it. That proved loading only, not real review work or effectiveness.

  2. 15 Oct 2026

    Retired, then copied

    That setup was retired and standalone model policies were copied straight into project instruction files instead. It worked locally, but the same personal defaults now lived in many places. Edits in one project didn’t reach the others, the copies drifted, and it became hard to tell a genuine project rule from one person’s habit.

  3. 7 Nov 2026

    Researching fixed teams

    The next idea was a fixed architect/builder/reviewer team as a skill. Research showed that such teams, fresh-context reviewers and capped loops already existed. What remained was narrower: keep personal configuration and execution records out of project knowledge. Research notes.

  4. 8 Nov 2026

    A profile, scoped roles, private records

    A personal profile outside projects; one writer per artifact; independent reviewers with neutral packets; a private records directory; only durable outcomes handed back. Honest labels throughout: requested is not attested, fresh is not isolated, advisory is not enforced. Implemented and structurally validated the same day.

  5. 8 Nov 2026

    Two small trials, mixed results

    A documentation pilot, with the skill added alongside existing rules, and a code-task pilot, with the skill replacing cleaned rules. Five task pairs each. Neither met its coordination target. Experiment notes.

  6. 8 Nov 2026, after the trials

    Installation and the cleanup

    The skill was installed for personal use and duplicated model clauses were removed from personal global instructions. Then came the project-by-project cleanup.

The painful partWhat the cleanup taught

Removing copied personal policy from existing projects was the most instructive step, because it was not mechanical.

  • Not bulk deletion. Matching policy text turned up in instruction files across several repositories, and each needed individual review.
  • Project constraints survived. Publication, privacy, approval and genuine product constraints had to survive the migration. The current owner decision superseded earlier personal model choices; removing them did not authorize changing product behavior.
  • History must survive. Earlier decisions and evidence that mention past model assignments are part of the record. Cleaning up must not rewrite it.
  • Defaults had reached runtime. Some personal defaults had spread beyond prose into runtime checks, so removing them changed behavior, not just documentation.
  • Adoption records are project facts. A project’s record of which documentation method it adopted, when, and where its entry point is must survive when personal settings are removed. Otherwise later sessions lose track of how the project is maintained.

That is the clearest case for the boundary this project draws. If personal preferences never enter project files, there is nothing to migrate later.

NowWhere it stands

Experimental and pre-release. The owner has chosen the MIT License and github.com/jaredchu/agents-collab as the public repository. The evidence supports the configuration boundary as a workable idea. It does not show general productivity gains or a new orchestration method, and it is not offered as one.
