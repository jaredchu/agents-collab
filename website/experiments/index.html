Notebook entry · 8 November 2026

Two small, honest trials

A structural validation, then two pilots of five paired real tasks each. Neither pilot met its coordination target. Here is what was measured, and what it cannot tell you.

Read this first
  • Five paired real tasks per pilot, one owner, related tasks, one execution per arm. No statistical or general causal inference.
  • Durations are summed observed model-call time, not human minutes or end-to-end wall time. Shared parent work and native review time are outside them.
  • Unknown usage is unknown, not zero. No complete cost was measured.
  • Raw evidence is private. These are selective, sanitized summaries, not independently auditable traces.
  • Both pilots ran before installation. Later real use is not a controlled experiment.

Each pilot had a rule fixed in advance: the skill should cut coordinator time or coordinator command count by at least 20%. Reviewers saw unlabeled bundles, but could plausibly infer style; blinding was not guaranteed.

00 · Before the pilotsStructural validation

Privately, 52 unit tests passed for the validator and package assets, and nine simulated initial scenarios plus two focused follow-up scenarios passed. They covered solo work without Git, unsupported required effort, exhausted review caps, resuming a running assignment, delegation restrictions, unenforceable deadlines, records overlap and changed review inputs. Two independent reviewers finished one initial round and one focused follow-up with no remaining material finding.

Capability responses in those scenarios were simulated. That shows a coherent procedure, not production safety. The public test suite drops one private-profile test and adds repository checks; its result will be reported when it is run.

01 · Additive documentation pilotAdding the skill on top of an existing workflow

Five unfinished documentation and decision-support tasks from one project, each done twice: the existing workflow, and the same workflow plus the skill and a private profile. Writers, reviewers, sources, acceptance criteria, word limits and round caps were matched; writer order alternated.

Coordinator time and commands both rose. Material findings in both arms sat in a single task and were addressed after one bounded correction round. Because the skill was added alongside existing rules, the benefit that motivated it, removing duplicated policy, was not measured.

02 · Replacement code-task pilotReplacing cleaned rules with the skill

Five real implementation tasks in one application, each from the same frozen code. The baseline kept the existing instructions; the skill arm used cleaned copies with personal model clauses removed, plus the skill and a private profile. Models and reasoning requests were explicitly matched, and both arms got the same paired independent review.

Coordination threshold: not met

* Not a productivity claim. One baseline correction hit its supervised 480.510-second deadline and was stopped, leaving an incomplete usage receipt. Identical tool allowlists gave the two arms different permission outcomes for generated in-writer test commands, so their check workloads differed. With one execution per related task pair, these confounds rule out crediting the skill with the apparent reduction.

  • Final readiness required bounded repairs in both arms. A pre-existing integration race in the application stayed open; not every product risk was resolved.
  • The skill arm’s coordinator followed the profile’s single-review default; the parent imposed the paired review. Automatic or named-recipe routing was not established.
  • Moving personal policy out of project files did not break the workflow, and project-facing handoffs passed a limited scan for model and private-path details. That scan is not a privacy guarantee.

03 · After the pilotsInstallation and discovery

The unchanged package was then installed for personal use with an existing private profile. A fresh session’s skill catalog listed it, the profile passed structural validation and installed file hashes matched. That verifies discovery and structure at the time, not future routing, automatic selection for every task, or runtime effort.

04 · ReadingWhat the evidence supports, and what it doesn’t

Supported, narrowly

  • Separating personal settings from project files is workable in a Codex-led setup.
  • In these samples the skill did not reduce coordination effort.
evidence line

Not supported

  • General productivity, quality or cost gains
  • Other lead assistants; reliable automatic routing
  • Runtime effort attestation; filesystem isolation
  • Demand for the tool
